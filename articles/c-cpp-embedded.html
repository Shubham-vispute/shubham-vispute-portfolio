C/C++ for embedded systems

A practical checklist for writing predictable low-level code.

Bit manipulation

#include <stdint.h>

#define BIT(n) (UINT32_C(1) << (n))

static inline uint32_t set_bit(uint32_t value, unsigned int bit)
{
    return value | BIT(bit);
}

static inline uint32_t clear_bit(uint32_t value, unsigned int bit)
{
    return value & ~BIT(bit);
}

static inline int read_bit(uint32_t value, unsigned int bit)
{
    return (value & BIT(bit)) != 0;
}

Ensure the bit index is within the width of the type. For hardware registers, use the register definitions and access rules supplied by the platform; do not assume a plain C variable is a safe substitute for memory-mapped I/O.

Embedded review checklist

  • Use fixed-width integer types when register widths matter.
  • Understand lifetime, ownership, stack usage and heap allocation.
  • Use volatile only for its intended compiler-access semantics; it is not a thread-synchronization primitive.
  • Consider race conditions, interrupt context and critical sections.
  • Check error paths, boundary conditions, integer overflow and timeout handling.
  • In C++, understand RAII, references, smart pointers, object lifetime and virtual dispatch costs.

Interview topics to practise

Pointers and arrays, static storage, const correctness, bitwise operations, memory segments, process versus thread, mutex versus semaphore, deadlock prevention, circular buffers, function pointers and C++ object lifetime.

Code is illustrative. Compile and test in your own target/toolchain and follow your project's coding standard.
