How management data can travel from a service to a standard API.

D-Bus role

D-Bus is an inter-process communication mechanism. Services expose objects, interfaces and properties; other services can discover objects and read or update properties according to the interface and policy.

Redfish role

Redfish is a RESTful management API model with JSON payloads and standardized resources. In OpenBMC, bmcweb can map internal system state to Redfish resources, subject to the implementation and available data.

Debugging checklist

  • Confirm the systemd service is active and inspect its logs.
  • Use D-Bus introspection tools to check object paths, interfaces and properties.
  • Check service ownership, interface names and property types.
  • Query the relevant Redfish endpoint and inspect status codes and response JSON.
  • Verify that the needed inventory or sensor objects are exposed to the Redfish implementation.

Example commands

systemctl status your-service
journalctl -u your-service
busctl tree xyz.openbmc_project.Example
curl -k https://BMC_ADDRESS/redfish/v1/

Use the actual service name, D-Bus destination and endpoint for your image. Official project: OpenBMC on GitHub ↗
